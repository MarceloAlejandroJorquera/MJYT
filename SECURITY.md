# Security policy

## Supported release

Security reports should target the latest published MJYT release. At initial publication, that is `v1`.

## Reporting a security issue

Please do **not** post exploit details, credentials, private URLs, or other sensitive material in a public issue.

If GitHub private vulnerability reporting is enabled for this repository, use it. Otherwise, open a minimal public issue stating that you have a security-sensitive report and need a private contact path; do not include the sensitive details in that issue.

A useful report should include:

- MJYT version.
- Windows version and architecture.
- A concise description of the security impact.
- Reproduction steps that do not expose private credentials or copyrighted/private media.
- Whether the issue requires a particular media type or workflow.

## Scope notes

MJYT v1 does not support account-authenticated, private, members-only, rented/purchased, or DRM-protected media. Reports that depend on bypassing those boundaries are outside the supported v1 product scope.
